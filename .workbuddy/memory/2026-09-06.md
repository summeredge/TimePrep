## start.bat 改造：按项目子目录放依赖 + 重写以消除诡异错误

- **用户原有约定**：`PythonEnvs\` 下每个项目一个子目录（已有 `local-review-launcher`、`pi-data-viewer`、`pi-data-viewer-ui` 等）。
  我最初把整个 venv 直接放 `PythonEnvs\` 顶层，破坏了约定 —— 已被纠正。
  现在正确的路径：`C:\Users\shaoy\Documents\PythonEnvs\industrial_timeseries_tool\`
- **`start.bat` 重写要点**：
  - 项目子目录名从 bat 所在目录自动派生（`for %%I in ("%~dp0.") do set "PROJECT_NAME=%%~nI"`）
  - 依赖检查抽到独立脚本 `_check_deps.py`，避免在 .bat 里拼装 `python -c "import pandas, ..."` 这种
    带逗号/空格的长串 —— **这正是旧 bat 产生 `'local'` / `'from'` / `'eady'` / `'ncies'` 之类
    "X 不是内部或外部命令" 碎片的根因**。cmd 在某些环境下会把带逗号的 `set "VAR=..."`
    解析错位，导致后续行被当成命令执行。
  - 所有 `set` 集中放到脚本顶部，避免和 `(...)` 块内 `%VAR%` 解析时序冲突
  - 用 `goto` 而非嵌套 `if (...)` 块来处理"venv 有/无"分支，更可控
- **跨工具核查**：因为沙箱禁止 `cmd.exe`，无法双击 bat，只能：
  1. 把 bat 中每条命令单独跑一次，验证 exit code 与输出
  2. 用 `for` 派生 `PROJECT_NAME`、用 helper 脚本判断依赖、用 venv 启 server 这三条都 OK
  3. 最终一次跑通：4 个分支（定位 python / 本机依赖 / venv 依赖 / 空 venv 模拟 ask 分支）+ HTTP 200
- 旧 bat 输出里有 "Dependencies found in local python, using: python" 这种文案 —— 新 bat 已经改成
  "All dependencies found in local python."，看到旧文案说明用户还在跑旧 bat。

## Web 弹窗 bug 修复（关闭 / 向上一级 / 选择当前目录 点不动）

- **现象**：进页面后弹窗直接顶在最上层，"关闭"、"向上一级"、"选择当前目录" 三个按钮点不动，
  也无法关掉。用户截图：`@image#1:Clipboard_Screenshot.png`。
- **根因**：`web/index.html` 里 `.modal { display: flex; }` 这条全局规则覆盖了 HTML 原生
  `hidden` 属性 —— 浏览器规范里 `display` 优先级高于 `hidden`，所以弹窗在加载时就已经可见，
  `openPicker()` / `closePicker()` 切换 `hidden` 完全不生效；同时 `.modal` 容器没显式声明
  `pointer-events`，按钮即使出现也可能被外层拦截。
- **修复**（同文件 CSS + JS）：
  1. `.modal[hidden] { display: none; }`  —— 让 `hidden` 真正生效
  2. `.box [hidden] { display: none; }`  —— 解决弹窗内个别元素
  3. `.modal .box { pointer-events: auto; }`  —— 显式放行点击
  4. JS 加点击背景关闭：监听 `modal` 的 `click`，判断 `e.target === modal` 时调用 `closePicker()`
- **验证**：
  - `grep -c '\.modal\[hidden\]' index.html` → 1（样式确认存在）
  - `node --check` 前端 JS → 语法 OK
  - `curl --noproxy '*' http://127.0.0.1:8765/api/list?...` → 200，目录列表正常
- **用户侧下一步**：刷新页面（Ctrl+F5 强刷）后再次打开文件选择器验证三按钮可点。
  start.bat 不用重启，server 是直读磁盘的 `web/index.html`。

## start.bat 双击后打不开网页（第二轮回退）

- **症状**：双击 `start.bat` 后命令行窗口**一闪就关**，浏览器没起来也没报错。
- **根因**（这次真正命中的）：
  - 旧版第 45–49、54–59 行用了
    ```
    if not errorlevel 1 ( echo ... & set "RUN_PY=..." & goto start )
    ```
    在 cmd 里**代码块 `(...)` 内的 `set` 副作用不会传到块外**，所以 `set "RUN_PY=..."`
    执行完就被吃掉了，跳到 `:start` 时 `%RUN_PY%` 仍是空。
  - `%RUN_PY%` 为空 → `"%RUN_PY%" "%SERVER%" %PORT%` 退化成空指令前缀，
    server 根本没被起，bat 走到底部 `pause` 但因为进程提前结束，窗口看不到就关了。
  - 加之最后一行 `pause` 前面**没有 `errorlevel` 检查**，server 真没起来时窗口不会停。
- **修复**（同文件 `start.bat`）：
  1. 把这两处 if 改成 `if errorlevel 1 goto ...` / `:label` / `set ...` / `goto start`
     —— 让 `set` 落在脚本顶层，不再嵌进 `(...)`。
  2. `:start` 标签下加自检 `if "%RUN_PY%"=="" ( echo [ERROR] & pause & exit /b 1 )`，
     若仍走到空状态会明确报错而不是静默退出。
  3. server 退出后加 `if errorlevel 1 ...` 把非零退出码显示出来，再 `pause`，
     任何失败都会留窗口、能看日志。
- **附带清理**：发现项目目录下多了两个 0 字节的 `start` 和 `ask` 文件（来源不明，
  可能是历史误操作或 bat 错误重定向的残留），非 git 工作区，已用 `rm -f` 删掉。
- **沙箱侧验证**：cmd.exe 被沙箱禁止调用，无法双击 bat；改用 venv python 直接起 server
  组件做端到端验证：`curl --noproxy '*' http://127.0.0.1:8765/` → HTTP 200，链路正常。
- **用户侧下一步**：
  - 双击 `start.bat`（之前那两个 0 字节文件已清掉，不会再被误触发）。
  - 应该会看到三行 echo：依赖检查结果、`Starting server: http://...`、
    浏览器会自动打开。
  - 若还是不开：现在窗口会留住，能看到日志内容贴给我即可定位。
